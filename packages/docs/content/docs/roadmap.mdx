This is Uji's roadmap, not a parity checklist for another project. The target is the core described by the
[design record](/docs/design): one durable conversation model, a small agent loop, peer clients, replaceable
providers and tools, and host-owned policy. The current source and tests decide what exists today.

External harness implementations are used as adversarial references for crash windows, races, and API
questions. Their register layouts, method names, storage backends, and feature counts are not Uji acceptance
criteria.

## How status is assigned

| Status                | Meaning                                                                                  |
| --------------------- | ---------------------------------------------------------------------------------------- |
| Exists                | The named source and tests implement the stated contract end to end                      |
| Partial               | Useful machinery exists, but a named correctness or product requirement is still missing |
| Not started           | The package or contract is absent from source                                            |
| Deliberate divergence | Uji has considered the reference design and chosen a different contract                  |

An interface alone is not completion. A durable feature also needs recovery behavior and tests for its crash
boundaries. A client demo is not a reusable host contract. A TypeScript annotation is not runtime validation.

## Today

Every package is private and unpublished. "Exists" means the code is present and runnable in this workspace;
it does not mean the API is stable or production-ready.

| ----------------------- | ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

## M0: Make the existing core trustworthy

These are release blockers for the current durable core. They precede new surface area because every client,
plugin, approval flow, and subagent would inherit these semantics.

| ID        | Status  | Required outcome                                                                                                                       | Evidence for today's verdict                                                                                                                                           |
| --------- | ------- | -------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GAP-C01` | Exists  | Serialize admission per head so two concurrent `prompt()` calls cannot both be accepted                                                | `startPrompt()` installs pending admission synchronously; cross-process contenders resolve through the run-claim CAS                                                   |
| `GAP-C02` | Partial | Make `prompt`, queue, abort, resume, and close one coherent lifecycle state machine                                                    | Close now cancels pending admission and active work idempotently; head state remains split across pending and active operation fields                                  |
| `GAP-C03` | Partial | Define durable provider intent and atomic response/usage settlement, including the policy for an uncertain provider call after a crash | `step_attempt` reserves neither response nor usage identity; response entry and usage record are separate commits                                                      |
| `GAP-C04` | Partial | Settle every assistant tool call exactly once, including calls skipped after abort                                                     | The loop can stop a sequential or parallel tool batch when the signal aborts, leaving later calls without `ToolResultMessage` settlements                              |
| `GAP-C05` | Partial | Isolate observers so a throwing or slow subscriber cannot change agent execution or prevent other subscribers from receiving an event  | Listener errors become `handler_error`, but listeners are still awaited serially, so a slow observer delays the run                                                    |
| `GAP-C06` | Partial | Add harness-level race, abort, crash-point, resume, and observer-failure tests                                                         | Tests cover rapid admission, cross-process abort, SIGKILL resume, fenced takeover, and terminal reconciliation; exhaustive crash-point and slow-observer drills remain |
| `GAP-C07` | Partial | Use collision-resistant durable IDs and validate persisted/wire values at runtime                                                      | `newId()` keeps eight hex characters from a UUID; schema interfaces and custom entry data are accepted without runtime decoding                                        |
| `GAP-C08` | Exists  | Keep the conversation and tool-result part contract strict end to end                                                                  | Core, sessions, providers, and both demos use `Message`; tool results accept only discriminated text/image parts and the v0 Responses-item layer is deleted            |
| `GAP-C09` | Partial | Close every owned resource and prevent process or repository bookkeeping from growing across repeated opens                            | Harness close releases provider-session leases and active Bash groups; deliberately daemonized commands remain outside process ownership                               |
| `GAP-C10` | Partial | Index an explicit searchable-text projection, never raw entry JSON or base64 image payloads                                            | SQLite FTS triggers index the serialized entry payload, which can include images, reasoning metadata, and provider fields                                              |

M0 is complete only when the behavior is represented in tests, not when comments describe the intended race
handling. Uji may implement this with transactions, a serialized head actor, an explicit operation state, or a
smaller equivalent; copying another implementation's internal register scheme is not required.

## M1: Finish Uji's durable session surface

These are blueprint requirements or prerequisites for them. Their public shape should be decided after M0 fixes
the lifecycle they expose.

| ID        | Status      | Work item                                                                                                      | Existing foundation                                                                                                                              |
| --------- | ----------- | -------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| `GAP-D01` | Partial     | Expose multiple heads with per-head runner ownership and admission; clients may observe without ownership      | Storage methods already take a head name, participant admission is open, and run claims are head-scoped; `AgentHarness` still hardcodes `"main"` |
| `GAP-D02` | Not started | Bound model context with explicit compaction entries and overflow handling                                     | The loop has a `transformContext` seam; the harness currently loads every message on the branch                                                  |
| `GAP-D03` | Partial     | Add branch navigation, fork, checkpoint, and revert contracts                                                  | Parent-linked entries and `moveHead()` exist; the harness and repository expose no complete workflow                                             |
| `GAP-D04` | Partial     | Provide reconnect-safe snapshots and a durable terminal outcome query                                          | `watch({ afterSeq })` replays the durable log then streams live items; there is no projected snapshot or direct terminal-status query            |
| `GAP-D05` | Partial     | Expose queue inspection and cancellation with stable run ownership                                             | `pendingQueue()` inspects and `cancelQueued()` writes the cancellation tombstone; ownership across runs is still provenance only                 |
| `GAP-D06` | Partial     | Define one backend conformance suite and prove the storage interface with a second implementation              | `SessionRepo` and `SessionStorage` are interfaces; tests instantiate SQLite directly                                                             |
| `GAP-D07` | Not started | Add storage versioning, ordered migrations, and newer-version refusal                                          | SQLite creates the current schema with `CREATE TABLE IF NOT EXISTS` and records no version                                                       |
| `GAP-D08` | Partial     | Make usage and operation status queryable without replaying internal log details                               | Usage and terminal records exist, but there is no public operation/status projection                                                             |

| `GAP-D10` | Partial     | Replace direct local-path assumptions with an explicit execution environment and optional workspace capability | Bash operations are injectable; file tools still capture a `cwd` and call the local filesystem                                                   |

## M2: Build one host contract for peer clients

Goal: clients speak a versioned, language-neutral contract and never create a second session model. The first
wire must cover the CLI's core use cases as well as the desktop demo; extracting the desktop facade verbatim
would be too narrow.

| ID        | Status      | Work item                                                                                                           | Evidence                                                                                                                            |
| --------- | ----------- | ------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| `GAP-H01` | Not started | Create `@uji-ai/protocol` with runtime-validated requests, responses, errors, parts, events, snapshots, and cursors | No `packages/protocol` directory exists                                                                                             |
| `GAP-H02` | Not started | Create `@uji-ai/server` as the host for sessions, providers, tools, policy, and event fan-out                       | No `packages/server` directory exists                                                                                               |
| `GAP-H03` | Not started | Create `@uji-ai/client` and prove the same contract from desktop, CLI, and a non-TypeScript client                  | No `packages/client` directory exists                                                                                               |
| `GAP-H04` | Partial     | Define provider discovery, auth status, login interactions, model selection, and credential-store ownership         | `@uji-ai/ai` has the primitives; `production-dependencies.ts` makes the desktop product choices                                     |
| `GAP-H05` | Partial     | Define session create/list/open/prompt/steer/follow-up/abort/resume/snapshot/watch/close with typed outcomes        | Core owns most primitives; the desktop API projects only its product needs and drops suspended operations                           |
| `GAP-H06` | Partial     | Carry every event and part without flattening, including reasoning, tools, usage, and images                        | Desktop forwards running state and text deltas, then reloads message entries for snapshots                                          |
| `GAP-H07` | Partial     | Separate protocol identity from UI presentation and remove Core types from the public client contract               | Core stays out of the renderer at runtime, but `desktop-api.ts` uses `MessageEntry` as its shared message type                      |
| `GAP-H08` | Partial     | Specify graceful host shutdown, active-run policy, and command cleanup                                              | `UjiHost.close()` closes its active harness, session, repository, and profile repository; process-level guarantees remain undefined |

The desktop demo now supports agent profiles, per-agent conversation selection, editing agent instructions, and
repository teardown. Those are product features, not proof that the shared host layer exists.

## M4: Run recreate-all proofs

The blueprint's product test is not a feature-count contest. A small set of Uji primitives should be able to
recreate materially different products without private session models.

| Proof                               | What it must exercise                                                                            |
| ----------------------------------- | ------------------------------------------------------------------------------------------------ |
| Coding agent                        | Workspace tools, guidance, checkpoints, permissions, compaction, and crash recovery              |
| Desktop and web chat on one session | Snapshot/watch correctness, multi-client fan-out, images, abort, and reconnect                   |
| Linear-style agent                  | Identity, ACLs, triggers, connectors, approvals, and durable background work                     |
| Notion-style agent                  | Structured content parts, app-owned tools, provenance, and optional workspace                    |
| Subagent workflow                   | Multiple heads or equivalent child execution, suspension, usage attribution, and one event model |

## What Uji takes from external harness reviews

The reference review changes Uji's test plan more than its API design.

| Classification          | Decision                                                                                                                                                                                            |
| ----------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Adopt the problem       | Atomic admission, explicit effect uncertainty, total recoverable operation state, coherent tool-call settlement, snapshot/subscription race handling, schema evolution, and adversarial crash tests |
| Decide in Uji           | Whether the durable mechanism is a transaction, head actor, state record, or another smaller abstraction; exact compaction and fork semantics; public error and event names                         |
| Defer until required    | Multiple concrete storage backends, manual drive mode, a broad hook registry, and branch indexes                                                                                                    |
| Reject as a parity goal | Matching another project's register namespace, UUID version, backend count, API names, SQLite layout, or every operation and hook solely for parity                                                 |

## Dependency order

1. Close `GAP-C01` through `GAP-C10` and prove them with harness tests.
2. Settle the durable session surface (`GAP-D01` through `GAP-D10`).
3. Freeze parts, events, errors, snapshots, and cursors in `@uji-ai/protocol`.
4. Build the host and clients against that contract.
5. Add skills, plugins, approvals, subagents, identity, triggers, and connectors.
6. Use the recreate-all proofs to remove abstractions that do not earn their place.

This order is a dependency graph, not a date forecast. New feature work may prototype earlier, but it does not
become a core guarantee until the layer beneath it is testable and durable.
