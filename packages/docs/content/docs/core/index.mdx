`@uji-ai/core` is the runtime that drives an assistant through turns and tool calls. It ships two
compositions of the same machinery. `runAgentLoop` is the loop itself: you inject a stream function,
a tool list, and an event sink, and it returns the new messages when the run ends. It holds
everything in memory and writes nothing. `AgentHarness` wraps that loop in a durable session: it
takes any `SessionStorage`, and `SqliteSessionRepo` supplies the SQLite implementation that ships.
Every run is bracketed by `operation_started` / `operation_finished` records, every tool call commits
a `tool_started` intent before the tool executes, and every message the loop emits is appended as a
write-once entry. The loop knows nothing about the harness: `agent-loop.ts` imports its public contracts and
neutral AI utilities, and the harness composes it through `runAgentLoopContinue`.

## Pick one

| Use case                                                                | Use this       | Why                                                                                                                                                     |
| ----------------------------------------------------------------------- | -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| One-shot task in a script or a test                                     | `runAgentLoop` | No database, no session id, no lease. Prompts in, `AgentMessage[]` out.                                                                                 |
| Embedding an agent inside a larger system that already owns persistence | `runAgentLoop` | You supply `AgentContext.messages` from your own store and keep the returned messages.                                                                  |
| Custom scheduling: you decide what a "run" is and when it stops         | `runAgentLoop` | `shouldStopAfterTurn`, `prepareNextTurn`, `getSteeringMessages`, `getFollowUpMessages` are yours.                                                       |
| A chat UI that must reload prior history                                | `AgentHarness` | `harness.session.getBranch("main")` returns the durable branch as `Entry[]`, oldest first; filter for `entry.type === "message"` to get the wire items. |
| A run that must survive a process crash                                 | `AgentHarness` | `AgentHarness.create()` reports suspended operations; `resume()` settles interrupted tool calls and continues.                                          |
| Anything that queues user input while the model is streaming            | `AgentHarness` | `steer` / `followUp` / `nextRun` are committed as `queue_enqueued` records before they are consumed.                                                    |

<Callout type="info">
  The harness is strictly additive. It calls `runAgentLoopContinue` with the same `AgentLoopConfig`
  fields you would pass yourself; its extra behavior lives in the `beforeToolCall` hook, the
  `getSteeringMessages` / `getFollowUpMessages` queue drains, and the event sink it installs.
</Callout>

## The loop

```ts title="run-loop.ts"
import { createModels, FileCredentialStore, openaiProvider } from "@uji-ai/ai";
import { createReadOnlyTools, runAgentLoop } from "@uji-ai/core";

const models = createModels({ credentials: new FileCredentialStore() });
const provider = openaiProvider();
models.setProvider(provider);
const model = models.getModel(provider.id, "gpt-5.6-luna");
if (model === undefined) throw new Error("model unavailable");
const streamFn = (requestedModel, context, options) =>
  models.streamSimple(requestedModel, context, options);

const newMessages = await runAgentLoop(
  [
    {
      role: "user",
      content: "Which files in this directory are TypeScript?",
      timestamp: Date.now(),
    },
  ],
  {
    systemPrompt: "You are a coding agent.",
    messages: [],
    tools: createReadOnlyTools(process.cwd()),
  },
  {
    model,
    convertToLlm: (messages) =>
      messages.filter(
        (message) =>
          message.role === "user" || message.role === "assistant" || message.role === "toolResult",
      ),
  },
  (event) => {
    if (event.type === "tool_execution_start") console.log(event.toolName);
  },
  undefined,
  streamFn,
);

console.log(newMessages.length);
```

`runAgentLoop` returns only the messages produced by this call: the prompts you passed plus every
assistant item and tool result. It does not return your prior history back to you.

## The harness

```ts title="run-harness.ts"
import {
  AgentHarness,
  inlinePlugin,
  SqliteSessionRepo,
  systemPromptPlugin,
  toolsFsPlugin,
} from "@uji-ai/core";
import { createModels, FileCredentialStore, openaiProvider } from "@uji-ai/ai";

const repo = new SqliteSessionRepo("./.uji/sessions.db");
const session = await repo.create();
const models = createModels({ credentials: new FileCredentialStore() });
const provider = openaiProvider();
models.setProvider(provider);
const model = models.getModel(provider.id, "gpt-5.6-luna");
if (model === undefined) throw new Error("model unavailable");

const { harness, suspended } = await AgentHarness.create({
  session,
  streamFn: (requestedModel, context, options) =>
    models.streamSimple(requestedModel, context, options),
  // The harness owns no prompt or tools; plugins contribute everything the model sees.
  plugins: [
    inlinePlugin(systemPromptPlugin("You are a coding agent.")),
    inlinePlugin(toolsFsPlugin()),
  ],
  env: { cwd: process.cwd() },
  model,
});

if (suspended.length > 0) {
  await harness.resume();
}

const result = await harness.prompt("Summarize package.json.");
if (result.ok) {
  console.log(result.value.kind); // "completed" | "aborted" | "failed"
} else {
  console.log(result.error._tag); // "HeadBusy" | "Closed"
}
```

<Callout type="warn">
`result.ok === true` does not mean the run succeeded. A run that failed inside the provider or the
harness still resolves as `Result.ok` carrying `{ kind: "failed", error }`; only the precondition
errors `HeadBusy`, `NoActiveRun`, `NothingToResume`, and `Closed` arrive as `Result.err`, and
storage failures throw `SessionError` instead. The three channels and the exact `error.code` values
are spelled out on [the harness page](./harness.mdx#lifecycle-api).
</Callout>

## Install and import

`@uji-ai/core` is a private workspace package. It is not published, and it has no build step: its
`exports` map points directly at the TypeScript source.

```json title="packages/core/package.json"
{
  "name": "@uji-ai/core",
  "private": true,
  "type": "module",
  "exports": {
    ".": "./src/index.ts",
    "./harness": "./src/harness/agent-harness.ts",
    "./plugins/system-prompt": "./src/plugins/builtin/system-prompt.ts",
    "./plugins/types": "./src/plugins/types.ts",
    "./session/sqlite": "./src/harness/session/sqlite.ts",
    "./session/types": "./src/harness/session/types.ts",
    "./types": "./src/types.ts"
  }
}
```

Depend on it from another workspace package with `"@uji-ai/core": "workspace:*"`, then import from the
package name. Two consequences follow from the missing build step:

| Requirement             | Reason                                                                                                                                     |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| Node 24 or newer        | The runtime executes the `.ts` sources directly; there is no emitted JavaScript to fall back on.                                           |
| `node:sqlite` available | `SqliteSessionRepo` imports `DatabaseSync` from `node:sqlite` at module load. Importing `@uji-ai/core` pulls it in through `src/index.ts`. |

The package's own scripts are `node --test test/*.test.ts` and `tsc --noEmit`. Neither produces
artifacts.

<Callout type="warn" title="Not built yet">
  There is no in-memory or JSONL session backend. The handle constructed by `SqliteSessionRepo` is
  the only implementation of `SessionStorage`, so a test that wants the harness goes through SQLite.
  `new SqliteSessionRepo(":memory:")` keeps it off disk.
</Callout>
