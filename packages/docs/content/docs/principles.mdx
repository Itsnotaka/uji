title: Principles
description: The constraints that keep June's loop, harness, providers, and clients composable
---

These are the settled rules. `blueprint.md` records open questions and dated decisions; this page states the
constraints the current source follows.

## 1. June owns its runtime

**June does not import another agent runtime as its implementation.**

The loop, durable harness, provider adapters, storage backend, tools, and clients live in this workspace. Source
files retain attribution where code was ported. Public contracts and documentation use June concepts.

## 2. Core does not know the harness

**The harness may compose the loop; the loop never imports the harness.**

`agent-loop.ts` depends on the neutral AI contracts and its local types. Session storage, crash recovery, queue
bookkeeping, and product behavior compose above it in `harness/` and host code. Deleting `harness/` does not
change the low-level loop contract.

## 3. One neutral conversation model

**Core, sessions, providers, and clients exchange `Message`, never a provider wire item.**

The canonical union is `UserMessage | AssistantMessage | ToolResultMessage`. Assistant content is text,
thinking, or tool calls; tool results contain text or images. Provider adapters encode at request time and decode
their event streams before the loop sees them. Sessions store the neutral values unchanged.

This is the core design test for new modalities: if the conversation or loop needs to carry it, the neutral wire
must represent it. Expensive conversion and presentation stay in hosts and clients.

## 4. Explicit composition

**Replaceable pieces are values passed at a composition root.**

| Block            | Contract                         | Shipped implementation                                     |
| ---------------- | -------------------------------- | ---------------------------------------------------------- |
| Session storage  | `SessionStorage` / `SessionRepo` | `SqliteSessionStorage` / `SqliteSessionRepo`               |
| Model runtime    | `Models` / `StreamFn`            | `createModels` and provider `streamSimple` implementations |
| Provider         | `Provider`                       | OpenAI Codex, OpenAI, and Anthropic factories              |
| Credential store | `CredentialStore`                | `FileCredentialStore`                                      |
| Tools            | `AgentTool` / `HarnessTool`      | Seven tool factories and three preset bundles              |

Hosts register the providers they support, select a concrete `Model<Api>`, and inject a `StreamFn` closure. Model
defaults and provider ordering are client policy, not fields added to the provider contract.

## 5. Plain TypeScript

**Public runtime contracts use ordinary TypeScript values, promises, event streams, and `AbortSignal`.**

Harness precondition failures use `Result` and tagged errors. Storage failures throw `SessionError`. Provider
failures terminate an `AssistantMessageEventStream` with an error message. These channels are explicit even
though they are not one universal error abstraction.

## 6. Clients are peers

**A host owns sessions, providers, tools, and policy; clients render and issue commands.**

The desktop main process hosts the harness and exposes a preload API. The CLI is another host composition over
the same core. A client that cannot render a content type ignores it; it does not require a second session model.

The language-neutral network protocol and reusable server/client packages are not built yet. Electron IPC is the
only process boundary currently proven.

## 7. Small default surface

**The system prompt is a caller-owned string and the default tool set stays obvious.**

| Factory                    | Tools                                   |
| -------------------------- | --------------------------------------- |
| `createCodingTools(cwd)`   | read, bash, edit, write                 |
| `createReadOnlyTools(cwd)` | read, grep, find, ls                    |
| `createAllTools(cwd)`      | read, bash, edit, write, grep, find, ls |

Skills, plugins, approval policy, and remote execution must compose around this foundation instead of turning the
loop into a product framework.

## 8. Durable history is not diagnostic logging

**Conversation history and process diagnostics are separate concerns.**

`SessionStorage.getLog()` is the ordered durable record clients can query. `AgentHarness.subscribe()` is the live
runtime event surface. Telemetry context can instrument provider and tool work without becoming a second
conversation log.
