Read order

Active tasks come first because they explain what is consuming capacity now. Each row shows the task, current activity, and settled cost so far.

Account headroom answers whether more work can start. Workspace usage is history, so it stays last. Task cost is already part of that total, not an amount to add again.

No new task entity

An in-progress task is a child session with an unfinished run. Its name, agent, state, and usage are projections over records Uji already needs for recovery.

task tool→child session
child log→run state + usage
TUI→in-progress row
completion→workspace total only
Do not estimate an open request. A task row sums committed usage records. The current provider request appears after its step settles.

Ownership

  • pluginCreate the child session and durable parent link
  • coreProject child run state and committed usage from the log
  • hostFetch and cache account limits beside provider auth
  • TUIJoin the 3 read models in one ephemeral card

Honest missing states

No active tasks is a quiet empty state. Missing provider data stays unknown instead of becoming 0%. Refreshing keeps the last value visible and marks it stale.
